# 04 · 工作区设计：对 Obsidian 范式的逆向操作

> 本文只做**范式层面的分析与反向假设**，不参考、不复用、不复制 Obsidian（Dynalist Inc.）的任何源码、界面皮肤、资源文件、文案或插件实现。
> 文中提及的交互范式属于行业公开常识，用于定位"我们要反过来做什么"，不构成对其表达的借鉴。
> 全部界面、渲染器、数据模型、术语体系均为本仓库自研，详见 `docs/ORIGINALITY.md`。

---

## 一、先把它拆开：Obsidian 到底靠什么成立

要逆向，先要准确描述被逆向的对象。Obsidian 的产品力并不来自"笔记编辑器"，而来自下面五条彼此咬合的**范式判断**。

| # | 范式判断 | 它带来的直接后果 |
|---|---|---|
| P1 | **文件即真相源**（file-over-app） | 知识库就是一个普通文件夹；软件只是 Viewer。用户永远拥有数据，换软件不丢东西。 |
| P2 | **关系是正文里的一串字符** | `[[双链]]` 写在 Markdown 里，因此关系=文本，可被 grep、可被 git diff、可被任何编辑器改。 |
| P3 | **图谱是链接的投影** | 图不是数据，只是把 P2 的链接画出来。删掉图，知识库毫发无损。 |
| P4 | **反向链接是字符串匹配的结果** | "谁提到了我的标题" —— 一次全文扫描即可得出，代价与规模线性相关。 |
| P5 | **三栏工作区 + 插件** | 左：文件树；中：编辑器；右：可插拔侧栏（backlinks / outline / tags / search）。插件生态补齐长尾。 |

这五条自洽得近乎优雅：**P1 保证信任，P2 保证可迁移，P3/P4 保证实现简单，P5 保证可扩展**。

但也正因为自洽，它有一个**从未被质疑的前提**：

> **关系是文件的附属品。文件存在，关系才存在；文件消失，关系瞬间消失。**

这就是我们要对它做逆向操作的支点。

---

## 二、逆向操作：把五条判断逐条翻转

我们不否定 P1（文件即真相源这条我们完全认同，也照做：NeoCosmos 的 Vault 同样是一个普通文件夹，`.md` 是唯一真相源，卸载软件不碰数据）。我们要翻的是 P2–P4。

### 反转 1：关系不是文本里的字符串 —— 关系是第一公民（突触）

| | Obsidian（正向） | NeoCosmos（逆向） |
|---|---|---|
| 本体 | 文件是实体，链接是文件的属性 | **突触是实体，文件是突触交汇处的投影** |
| 生命周期 | 删文件 → 链接消失 | 删文件 → 突触进入 `_graveyard` 归档（优雅遗忘），可复活 |
| 表达方式 | 只有 `[[链接]]` 一种 | 人写 `[[双链]]` 只是 7 类突触之一；其余 6 类由系统推导/由 Agent 回写 |
| 属性 | 无类型、无权重、不变化 | 有类型、有权重、会强化（LTP）、会衰减（LTD，下限 0.05 永不归零）、记录最近激活与建立者 |

**直接后果**：反向链接不再是"谁提到了我的标题"，而是"**哪些突触指向我，这条突触有多强、什么类型、上次走过是什么时候、是谁建的**"。它从字符串匹配升级为**带动力学的关系查询**。

### 反转 2：图谱不是投影 —— 图谱是管理界面

Obsidian 里图谱是"看看就好"的可视化。NeoCosmos 里**星图是所有知识卡片的管理网络**：

- 在星图上**点选卡片 → 直接跳转到该文档**（图是导航器，不是装饰）
- 按突触类型筛选、按权重阈值过滤、按记忆层着色
- 选中卡片时高亮其 N 跳邻域，并把激活扩散的实时结果画成能量脉冲
- 孤立点、矛盾对、待消歧项在星图上以不同标记暴露 —— **管理动作从图发起**

### 反转 3：关联不是一张清单 —— 关联是分型的卡片

Obsidian 右侧栏给你一列 backlinks。NeoCosmos 给的是**分型关联卡片**，每类卡片回答一个不同的问题：

| 卡片 | 回答的问题 | 数据依据 |
|---|---|---|
| 入链突触卡 | 谁以何种关系指向我、强度多少 | 入边（按类型分组，按权重排序） |
| 出链突触卡 | 我指向谁，其中哪些还是**断链**（目标不存在） | 出边 + 正文 wikilink 的解析结果 |
| 语义邻居卡 | 与我共享非域标签、结构上相近但不相邻的是谁 | `semantic_similar` 边 |
| 共现卡 | 谁和我总在同一语境出现 | `co_occurrence` 边 |
| 因果 / 时序卡 | 谁导致我、谁在我之前 | `causal` / `temporal` 边 |
| 沉淀卡 | 外部 Agent 曾就我产出了哪些问答沉淀 | `qa.json` 中引用本节点的沉淀 |
| 突触审计卡 | 这条关系的权重是怎么变成现在这样的 | 边历史（强化次数、最近强化、origin） |

**断链的关键创新**：Obsidian 里断链是一个"空链接"，点了会新建空文件。在 NeoCosmos 里，断链是**「待生长的突触」**——它是网络主动发出的邀请：这里缺一张卡片。一键生成时，新卡片会**自动继承所有指向它的突触**，而不是从零孤立地诞生。

### 反转 4：沉淀不是人写的 —— 沉淀是外部智能体的回写通道

这是 Obsidian 范式里**根本不存在**的角色。

人的笔记是"我写下的"。而 NeoCosmos 的**沉淀层**是：外部 AI Agent（通过 MCP / Skill）在回答问题的过程中，把**结论与问答对**回写进大脑知识库。它带来三个必须被设计进去的约束：

1. **来源可辨**：每条沉淀标记 `origin=agent`，与人写正文在视觉与数据上分列。
2. **全程审计**：任何写操作进 `journal.jsonl`，可溯源、可回放。
3. **绝不覆盖人写正文**：Agent 只能追加到沉淀区（`appendToSedimentZone`），或新建独立卡片。**系统永远不会改写用户手写的段落** —— 这不是产品选择，是红线。

于是"沉淀"模块不是"写笔记的地方"，而是**回写通道的控制台**：通道怎么接、流进来什么、哪些该固化成正式卡片、哪些该驳回。

### 反转 5：不靠插件 —— 能力内生

Obsidian 用插件生态补长尾。NeoCosmos 选择**能力内生**：可塑性、扩散检索、巩固、沉淀通道、星图，全部是内核的一部分，因为它们共用同一份突触状态。外挂插件无法做到——插件改不了关系的所有权。

## 三、工作区信息架构（落地形态）

```
┌──────────────────────────────────────────────────────────────┐
│ 命令轨：快速切换 · 扩散检索 · 突触筛选 · 记忆层 · 状态         │
├────────────┬─────────────────────────────┬───────────────────┤
│ 星图导航台  │  文档台                      │ 关联卡片栏         │
│            │                             │                   │
│ · 卡片树   │  面包屑 · 标题 · 元信息       │ ▸ 入链突触 (n)     │
│   (文件夹) │  ─────────────────────────  │ ▸ 出链突触 (n)     │
│ · 记忆层   │  Markdown 渲染 / 编辑         │   ⚠ 断链 (n)      │
│   分组     │  · 双链内联可点击跳转         │ ▸ 语义邻居 (n)     │
│ · 标签云   │  · 标签可点击                │ ▸ 共现 (n)         │
│ · 沉淀入口 │  · 断链以虚线标记            │ ▸ 因果/时序 (n)    │
│ · 星图入口 │  · 沉淀区以独立色块呈现       │ ▸ 沉淀引用 (n)     │
│            │                             │ ▸ 突触审计          │
├────────────┴─────────────────────────────┴───────────────────┤
│ 状态栏：卡片数 · 突触数 · 当前卡片突触强度 · 健康度 · 通道状态 │
└──────────────────────────────────────────────────────────────┘
                             ⋮
            按 G 或点「星图」→ 全屏 3D 突触网络
            （卡片管理网络：选卡 → 跳转文档；选类型 → 过滤）
```

**阅读—编辑—关联**是一个闭环，不是三个独立页面：

1. 在左栏或星图选中一张卡片 → 中栏打开它；
2. 中栏内联 `[[双链]]` 一点 → 直接跳转，并把跳转路径压入**导航历史**（可前进/后退）；
3. 右栏实时显示这张卡片的所有突触关系，点任一张关联卡片 → 又跳到它。
4. 断链处点"生长" → 新建卡片并**自动继承突触**。

## 四、与 Obsidian 的显式差异清单（原创性自证）

| 维度 | Obsidian 类产品的做法 | NeoCosmos 的做法 | 为何不可互相替代 |
|---|---|---|---|
| 关系存储 | 无存储，正文里解析 | 独立索引，带类型/权重/强化次数/最近激活/origin | 关系可脱离文件存在 |
| 关系强度 | 无 | 0.05–1.0 连续值，LTP/LTD 动力学 | "越用越准"无法靠字符串匹配实现 |
| 检索 | 全文/词面匹配 | 词面 BM25 + 沿突触扩散，RRF 融合 | 词汇零重叠但结构相邻也能召回 |
| 可解释性 | 命中即命中 | 每条结果给出"因 A → B → C 联想至此" | 可解释是架构产物，不是 UI 文案 |
| 图谱角色 | 可视化投影 | 卡片管理网络（跳转/筛选/管理动作发起点） | 图要能改数据，不只是看数据 |
| 断链 | 空链接，点击新建空文件 | 待生长突触，新建时自动继承全部入边 | 关系先于文件存在才有继承可言 |
| 外部写入 | 无（只有人写） | Agent 经 MCP 沉淀，origin 标记 + journal 审计 | 需要一个有约束的写入通道 |
| 遗忘 | 删除即消失 | `_graveyard` 归档，可复活 | 优雅遗忘是记忆体特征 |
| 时间维度 | 无 | 按天衰减 + 巩固"睡眠" + 三层记忆升降级 | 静态图谱没有时间轴 |
| 扩展方式 | 插件生态 | 内核内生 | 插件无法持有关系所有权 |

### 附：两处必须有的工程补充

1. **突触推导**（反转 1 的工程后果）
   关系是第一公民，就意味着"库里没有双链"不能导致网络为空。推导器从结构信号（标签、共现术语、时间邻近、目录层级）里长出四类突触，全部标记 `origin='derived'`，**不动正文**。
   实测：330 张卡片 → 一次推导新增 1367 条突触，耗时 35 ms。

2. **显示稀疏化**（反转 2 的工程后果）
   既然星图是管理界面，它就必须在大库下仍然可用。几千条突触全画出来只会糊成一团白。
   策略：按权重优先 + 每卡最多 N 条最强突触（kNN 式），保证每张卡片都还在图上；配合密度档位（稀疏/标准/完整）、按边数自适应的透明度与泛光强度、以及"簇 = 域或一级目录"的布局分簇（否则无域的库会被簇心引力拽成一点）。

## 六、明确不做（红线）

- 不做、也不借用任何第三方笔记产品的主题、图标、界面布局文案或插件格式。
- 不做云同步、账号体系、多人协作、移动端。
- 不让任何自动化（含 AI）改写用户手写正文：只能追加沉淀区或新建独立卡片。
- 不做"另一个 Markdown 编辑器":编辑器只是文档台的两种模式之一，产品本体是突触网络。
